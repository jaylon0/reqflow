# ReqFlow V7 UX & Agent Improvements Design Spec

> **Status:** Draft
> **Date:** 2026-05-22
> **Scope:** 17 improvements across 5 categories
> **Trigger:** Test session `run-20260521-205023` exposed systemic issues

## Problem Statement

Test session `run-20260521-205023` (fin-ktms 仓库, full-auto 模式) revealed 5 categories of issues:

1. **Confidence reports** are too sparse, no visualization
2. **Stage reports** lack detail, no charts, no trend
3. **Multi-agent collaboration** is fake — one agent plays multiple roles
4. **MCP calls are silent** — user sees nothing until stage completion
5. **Acceptance stage** doesn't present clear options

Additional issues discovered during design: dashboard state desync, agent timeout handling, test execution strategy rigidity, artifact integrity gaps, spec drift undetected, gate schema inconsistency.

#### A2. Gate Schema in MCP Tools (Item 15)

**Problem:** `reqflow_verify` tool description doesn't include evidence schemas, causing agents to guess field names.

**Solution:** Embed full schema in tool description:

```python
@tool
def reqflow_verify(run_id: str, gate: str, evidence: dict):
    """验证质量门禁。

    gate 可选值及 evidence schema:

    design-gate:
      meta_spec: str (truthy) - Meta Spec 路径
      feature_spec: str (truthy) - Feature Spec 路径
      tech_plan_stages: int >= 2 - 技术方案阶段数
      completeness_checked: bool - 是否完成完备性检查

    tdd-gate:
      failing_tests_count: int > 0 - 失败测试数量（必须 > 0）
      test_plan: bool (truthy) - 测试计划是否存在

    completion-gate:
      build_success: bool - 构建是否成功
      tests_passing: bool - 测试是否全部通过
      spec_compliant: bool - 是否通过 Spec 合规审查
      completed_items: int - 已完成工作项数
      total_items: int - 总工作项数

    compliance-report:
      verification_evidence: str (truthy) - 验证证据
      review_evidence: str (truthy) - 审查证据
      test_evidence: str (truthy) - 测试证据

    若字段名或类型不匹配，返回精确错误信息。
    """
```

**Error message enhancement (Item 17):**

```python
def _validate_evidence(gate: str, evidence: dict) -> str | None:
    schema = _GATE_SCHEMAS[gate]
    missing = []
    wrong_type = []
    for field, spec in schema.items():
        if field not in evidence:
            missing.append(f"  - {field}: {spec['description']} (要求 {spec['type']})")
        elif not spec['check'](evidence[field]):
            wrong_type.append(f"  - {field}: 值 {evidence[field]} 不满足 {spec['type']}")

    if missing or wrong_type:
        parts = ["门禁未通过:"]
        if missing:
            parts.append("缺失字段:")
            parts.extend(missing)
        if wrong_type:
            parts.append("类型错误:")
            parts.extend(wrong_type)
        parts.append(f"请修正后重新调用 reqflow_verify(gate=\"{gate}\", evidence={{...}})")
        return "\n".join(parts)
    return None
```

#### B3. Artifact Verification (Item 13)

**Trigger:** End of each stage that modifies files.

**Logic:**

```python
def verify_artifacts(claimed_changes: list[dict]) -> dict:
    results = []
    for change in claimed_changes:
        path = change["path"]
        if change["action"] == "create":
            exists = Path(path).exists()
            results.append({"path": path, "claimed": "create", "exists": exists, "pass": exists})
        elif change["action"] == "modify":
            exists = Path(path).exists()
            # Could check git diff for content verification
            results.append({"path": path, "claimed": "modify", "exists": exists, "pass": exists})
    return {"all_pass": all(r["pass"] for r in results), "details": results}
```

#### C2. Agent Timeout & Degradation (Item 8)

**Timeout strategy:**

```
subagent 启动后:
  - 60s 无响应 → 标记 TIMEOUT，重试 1 次
  - 重试仍 TIMEOUT → 标记 SKIPPED
  - required agent SKIPPED → 报告 BLOCKER，等待用户决策
  - optional agent SKIPPED → 继续，在报告中标注降级
```

**Output format on timeout:**

```
⚠️ architecture-agent 超时 (60s)，重试中...
⚠️ architecture-agent 重试后仍超时，已标记 SKIPPED
❌ required agent SKIPPED — 等待用户决策

选项:
1. 重新派遣 (我将重试)
2. 跳过此 agent (降低置信度)
3. 中止流程
```

#### D3. Test Execution Strategy Adaptation (Item 12)

**In SKILL.md, define probe logic:**

#### 测试执行策略

不得假设测试命令格式。必须按以下顺序探测：

1. **首选:** `mvn -pl {module} -am -Dtest={TestClass} test`

   - 成功 → 记录完整 classpath 命令

⚠️ 不得报告"测试通过"除非实际执行了测试且 Tests run > 0
⚠️ 必须在 evidence 中记录最终使用的测试命令

#### E1. Dashboard State Sync Fix

**Root cause:** `reqflow_report` doesn't update `current_stage_index` in state.

**Fix in `mcp_server.py` `_handle_report`:**

```python
def _handle_report(self, args):
    stage = args.get("stage", "")
    # ... existing logic ...

    # Fix: update state with current stage
    state = sm.load_state()
    stages = state.get("stages", [])
    if stage in stages:
        idx = stages.index(stage)
        sm.save_state({
            "current_stage": stage,
            "current_stage_index": idx,
            "steps_executed": state.get("steps_executed", 0) + 1
        })
    else:
        sm.save_state({"current_stage": stage})
```
