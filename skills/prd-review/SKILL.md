# prd-review

PRD 审查。评估需求完整性、技术可行性。

## 触发条件

- 新 PRD 需要评审
- 需求变更需要评估
- 需求澄清

## 方法论

### Step 1: 理解 PRD

1. 功能需求
2. 用户故事
3. 验收标准
4. 非功能需求

### Step 2: 评估完整性

| 维度 | 检查点 |
|------|--------|
| 功能完整性 | 是否有遗漏场景 |
| 边界条件 | 是否覆盖边界情况 |
| 非功能需求 | 性能、安全、可用性 |
| 依赖关系 | 是否有外部依赖 |

### Step 3: 技术可行性

1. 实现难度
2. 技术风险
3. 资源需求
4. 时间估算

### Step 4: 输出建议

1. 需要澄清的问题
2. 建议补充的内容
3. 技术风险提示

## 输出格式

```
## PRD 审查报告

### 需求概述
[PRD 的主要内容]

### 完整性评估
[是否有遗漏]

### 技术可行性
[实现难度和风险]

### 建议
[需要澄清和补充的内容]
```

## 注意事项

- 要从技术角度评估，不要只看需求描述
- 要关注边界条件和异常情况
- 要评估技术风险
- 要提出具体问题，不要泛泛而谈
