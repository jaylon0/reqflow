# tech-plan

技术方案撰写。调研现状，设计候选方案，制定实施计划。

## 触发条件

- 新功能需要技术方案
- 重构需要设计方案
- 技术选型需要评估
- 架构设计需要文档化

## 方法论

### Step 1: 理解需求

1. 功能需求（做什么）
2. 非功能需求（性能、安全、可扩展性）
3. 约束条件（时间、资源、技术栈）

### Step 2: 调研现状

1. 现有架构和技术栈
2. 相关代码和模块
3. 已有的类似实现

### Step 3: 方案设计

提供 2-3 个候选方案：

| 方案 | 优点 | 缺点 | 推荐度 |
|------|------|------|--------|
| 方案 A | ... | ... | ⭐⭐⭐ |
| 方案 B | ... | ... | ⭐⭐ |
| 方案 C | ... | ... | ⭐ |

**推荐方案：** [选择的方案及理由]

### Step 4: 实施计划

1. 模块拆分
2. 接口设计
3. 数据模型
4. 依赖关系
5. 时间估算

## 输出格式

```
## 技术方案

### 需求概述
[要解决什么问题]

### 现状分析
[当前架构和相关代码]

### 候选方案
[2-3 个方案对比]

### 推荐方案
[选择的方案及理由]

### 实施计划
[模块拆分、接口设计、时间估算]
```

## 注意事项

- 方案要有具体代码示例，不要只有抽象描述
- 要考虑向后兼容性
- 要评估技术风险
- 要考虑可测试性
