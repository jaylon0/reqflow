# retro

复盘分析。分析迭代过程，总结经验教训。

## 触发条件

- 迭代结束
- 项目里程碑
- 问题发生后
- 定期回顾

## 方法论

### Step 1: 收集数据

1. git log（提交历史）
2. 变更文件统计
3. 时间线
4. 问题记录

### Step 2: 分析模式

| 维度 | 分析 |
|------|------|
| 做得好 | 值得继续保持的做法 |
| 需改进 | 需要改变的做法 |
| 学到的 | 新的知识和技能 |
| 遗留的 | 未解决的问题 |

### Step 3: 输出建议

1. 具体改进措施
2. 优先级排序
3. 负责人
4. 时间节点

## 输出格式

```
## 复盘报告

### 迭代概述
[时间范围、目标、成果]

### 做得好
[值得肯定的地方]

### 需改进
[需要改变的地方]

### 经验教训
[学到的东西]

### 改进计划
| 措施 | 优先级 | 负责人 | 时间 |
|------|--------|--------|------|
| ... | 高/中/低 | ... | ... |
```

## 注意事项

- 要基于数据，不要凭印象
- 要聚焦改进，不要追究责任
- 要有具体行动项，不要泛泛而谈
- 要跟踪改进效果
